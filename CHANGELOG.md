# Changelog

## 2.0.0

The generators are rewritten in Go with `text/template`; the repository is the
Go module `github.com/masagroup/soft.gen/v2`. The Acceleo generators of v1 are
removed from the tree; they remain in the history, up to the `v1.x` tags.

### Same as v1

- The command line (`-m`, `-o`, `-p`, `-P`, `-t`, `-s`, `-v`, `-h`), the entry
  points of `-t`, the properties, the annotation keys and the generated code:
  a file generated by v2 is identical to the file generated by v1 once both are
  formatted (`gofmt` for Go), but for its first line (below).

### Changed

- One docker image, `masagroup/soft.gen`, holds every language; the
  language is the first argument: `masagroup/soft.gen go -m ...` replaces
  `masagroup/soft.generator.go -m ...`. The per-language images remain for v1.
- The version of soft.gen (`soft.gen -v`) is computed from Git by `version.sh`
  (the tag of the build, or a Go pseudo-version between tags). Each language
  keeps its own version (`soft.gen go -v`), as in v1: the version of the
  runtime its templates target (soft.go), in the VERSION file of the language,
  embedded in every build (`go install`, `go run ...@v2.x`) and set by
  `make version.<language> TO=vX.Y.Z`; v1 set it in its build.
- The generator is named after the command and the language, `soft.gen go`,
  in the first line of a generated file (`// Code generated by soft.gen go. DO
  NOT EDIT.`, v1 wrote `soft.generator.go`) and in `soft.gen go -v`.
- Every folder a run generates files in holds a manifest, `.soft.gen.yaml`: the
  generator, the version of the language and the nsURI of the package. A new
  version changes the manifests only, not the generated files.
  `--manifest=false` leaves them out.
- Property files (`-P`) may be Java `.properties`, YAML or JSON, by extension.
- The command line is built with urfave/cli v3: the options keep their v1
  names and short forms, and may also come from `SOFT_GEN_*` environment
  variables and from a configuration file (`--config`, YAML, JSON or TOML, read
  with cli-altsrc); the command line wins over the environment, which wins
  over the file.
- `--dry-run` lists the files without writing them; `--diff` prints the
  differences with the existing files, writes nothing and exits 1 on any
  difference; `--format` runs the external formatter of a language.
- Go files are formatted with `gofmt` in process: `go fmt` after a generation
  is a no-op.
- A file imports exactly the packages it uses: v1 maintained an import list per
  template.
- Any failure exits with code 1 (the v1 C++ and TypeScript generators exited 0
  after printing an error).
- A user code region that the model does not generate any more is reported as
  a warning; v1 wrote a `.lost` file beside the generated file.
- `--help` lists the templates and the properties of a language.
- The packages of the generator are internal (`internal/...`): the module
  exposes the command only, `cmd/soft.gen`.

### Fixed (Go)

- `Create<Class>FromContainer` qualifies the type of the container parameter;
  v1 wrote the bare class name, which did not compile when the implementation
  lives in another package than the interfaces. The output is unchanged when
  both are in the same package.
- Generic types (`eGenericType`, `eTypeParameters`) are read as their classifier
  type; v1 read them through EMF generics. The output is unchanged for the
  models of the project.

The fixtures (see TEMPLATES.md) revealed these v1 bugs, which v2 fixes; on
every other construct the output is the v1 output:

- The unsetter and the basic unsetter of an unsettable single containment or
  bidirectional reference declare their notification chain with `var` (v1's
  output did not parse).
- A string default value literal is escaped (v1 wrote quotes and backslashes
  raw, which did not parse).
- An attribute of a Go type the type table does not know, without default
  value, uses the zero value `*new(T)` in `EIsSetFromID`, `EUnsetFromID` and
  the tests (v1 wrote nothing, which did not parse).
- The type table has `int32` and `int8` rows: their test values are `int32(32)`
  and `int8(8)` (v1 wrote `int32()`, which did not compile).
- The `EDerivedOperationID` test qualifies the operation ids of the class
  outside the interface package; the mock tests of a class with operations
  only import `ecore` for `NewMockRun`; testify's `mock` and a model package
  named `mock` get distinct aliases (all three did not compile).
- The annotation of a parameter is created in the parameter (v1 called a
  getter named after the parameter, which did not exist or was another
  element's), and a nested annotation in its parent annotation (v1 created it
  in nil: it was lost).
- The features of a mixin extending a class keep their declaration order in
  `EDerivedFeatureID` (v1 used the order of a set difference).
- `rootExtendsMock` works (v1 failed generating the mocks).

### TypeScript

- `soft.gen ts` replaces `masagroup/soft.generator.ts` (v1.7.0 and the shared
  package mode of the v1 branch): same templates, properties and annotation
  keys. Its version follows soft.ts.
- The files are written in the layout prettier gives them with the options
  of soft.ts, the line width being the new `printWidth` property (default
  120): soft.ts's format step after a generation (removal of the unused
  imports, prettier) changes nothing. A file imports exactly the names it
  uses; v1 imported every name a template might use.
- The first line of a file is `// Code generated by soft.gen ts. DO NOT EDIT.`.

### Fixed (TypeScript)

- A class with several super types imports the types it uses itself (v1
  imported them from the files of its super types, missing some).
- The `namespaces` property applies to every identifier of the ecore module
  (v1 wrote `ecore.` in some of them).
- The package and factory implementations of another module are imported
  (v1 wrote them by their name, which did not compile).
- The package getter is always named after the package interface (v1 called
  `get<packageName>()` when an `interfaceName` rule renamed the interface),
  and a container type follows the `interfaceName` rule.
- A string default value literal is quoted and escaped, and an attribute of
  a type the type table does not know has the test value `null` (v1's output
  did not parse).
- The annotation of a parameter and a nested annotation are created in their
  element, as for Go.

### Not ported yet

- The C++ generator: use the v1 image (`masagroup/soft.generator.cpp`, v1
  tags) until it is ported.
